## 1. 一句话定位

**速影**是装在任意客户本机上的 **通用「剪辑 + 发布物料 + 辅助触达」工作室**：

把**该客户自己的**实拍片库，稳定变成 **能发的竖屏成片 + 配套文案/字幕/口播物料**，并在可控风险下 **辅助多平台发出与触达**。

- **产品**通用；**行业包**可插拔；**客户实例**只换路径与配置。
- **低配可运行**：素材先 coarse 快速入索引并可正常出片；Vision 只对生产候选按需用 9B 验证，不做默认全库 VLM 回填。
- **批量可安装**：首启必须检测实际内存/架构/磁盘并生成版本化安装计划；App 与远程部署共用模型选择、门禁和脱敏回执，不按机型名称猜配置。
- 「北京始峰伟业」= 首个样板客户，不是产品边界。
- 不是矩阵引流黑产工具，也不是全自动数字人直播间。

## 2. 你真正想做的是什么（目标澄清）

| 你心里的诉求 | 澄清后的产品目标 | 明确不是 |
|--------------|------------------|----------|
| 认真做完混剪项目 | 成片质量可签字、日更可运营 | 堆功能清单 |
| 多平台软文同步 | **一次成片 → 多平台文案适配包** | 替客户写无关软文站群 |
| 视频一键发布 | **发布队列 + 半自动/官方通道**，稳定发完计划条数 | 「绕开平台机器人检测」的全自动矩阵 |
| 多语言字幕/口播 | **人话脚本 → TTS → 声画同构成片** | 一上来就做数字人假脸 |
| 后台消息统一管理 | **未读提醒中枢 + 一键跳转官方端** | 全能跨平台客服台 / 硬扒私信绕登录 |

核心价值排序（优化后）：

```text
1. 成片「能发不丢人」（质量）
2. 每天稳定出够条数（产能）
3. 发出去有配套文案/字幕/口播（物料）
4. 发出去省事、可审计（分发）
5. 发出去之后知道有没有人找（触达提醒）
```

## 3. 做出来能做什么（能力地图）

### 对任意开通客户日常意味着什么

| 场景 | 今天/近期能做 | 完整方案落地后能做 |
|------|---------------|--------------------|
| 早上 | 挂盘 → 开 App → 扫新货 | 同上 + 日历自动开跑 |
| 出片 | 主题混剪、有 BGM、质检进 ready | Logo、打回学习、质量日报（按客户隔离） |
| 发前 | 人肉想文案、自己上传 | **一键导出：视频+封面+各平台文案+字幕+口播** |
| 发布 | 手动打开各 App 上传 | **队列里点「打开并填好」或官方 API 发；验证码时人工点一下** |
| 多语言 | 基本没有 | 英/其他语言旁白+字幕的成片变体 |
| 售后触达 | 各 App 里翻私信 | **本人账号由本机 Chrome 串行读取脱敏未读摘要，点一下跳进官方端人工回复** |
| 换公司 | 改代码/改脚本风险高 | **新建客户 + 选行业包 + 指路径**，不改引擎 |
| 语义运营 | coarse 能检索但证据层级与存量健康不够直观 | **语义体检 + 官方目录物品核验 + 物品专题 + 可暂停向量队列**，全程显示真实证据与状态 |

### 产品分层（对外可讲的三档）

| 档 | 名称 | 交付物 | 卖点一句话 |
|----|------|--------|------------|
| **Studio** | 混剪工作室 | 成片 + sidecar + 审片 | 片库进、能发的竖屏片出 |
| **Pack** | 发布物料包 | 文案多平台适配 + 字幕 + 口播轨 | 发出去不用再憋文案 |
| **Reach** | 触达助手 | 半自动发布队列 + 消息提醒 | 少切换 App，不碰风控红线 |

### Phase 12 · 语义证据、物品专题与向量运营（GSemanticOps · 离线实现完成）

> 本阶段代码、迁移、App 与自动验收已完成；真机新成片人眼验收未执行，不得把整 Gate 标为完全交付。

- [x] **语义体检**：按客户展示 coarse、官方目录证据、画面事实、strict 的覆盖率、缺口、失败原因与可执行修复；coarse 永不冒充 strict。
- [x] **官方目录物品核验**：导入有版本和摘要的官方目录，核验规范中文名称、分类与型号；目录证据和画面直接可见事实分层保存，目录不得替代 strict 视觉门禁。
- [x] **词池安全演进**：沿用唯一 canonical 词池、revision/SHA256、原子提升、archive/回滚与 Job 冻结；新增/修订词句必须绑定已核验事实和语义来源，经过生成与平台合规门禁。
- [x] **物品专题**：只允许围绕当前成片中有画面证据、且名称经目录核验或明确人工确认的物品生成专题；未知、冲突或仅目录候选不得写成画面事实。
- [x] **滚动避重**：cliplet 与规范化短句按近窗优先排除并渐进放宽；仅 ready 记账，禁止日/周满额熔断。
- [x] **规则实验室 v2**：在现有“AI 草稿→人工确认→版本冻结”上，增加语义体检、证据要求、物品专题、日周配额和表达布局规则；客户规则只能加严，不能放松 strict、READY_GATE 或专项硬锁。
- [x] **可暂停向量队列**：开始/继续只入持久队列；按首次资格时间最老优先；展示 `queued/running/completed/failed/abandoned` 真实状态；暂停放弃当前未完成请求但保留已完成并落盘的向量。
- [x] **双画幅冻结像素验收**：portrait 1080×1920、landscape 1920×1080；标题/字幕样式与绝对位置按画幅规则冻结并做最终字形验收，字幕时间对齐不变；物品中文名单列自上而下且不得侵入标题/字幕安全区。
- [ ] **验收**：多客户隔离、迁移/回滚、暂停/崩溃恢复、配额并发、像素回归、主冒烟与真机成片人眼验收全部通过。

## 6. 从各角度优化后的设计取舍

| 角度 | 优化结论 |
|------|----------|
| **商业** | 先卖 Studio 质量，再卖 Pack（文案口播），Reach 作加价项；不把封号风险写进承诺 |
| **合规** | 官方/半自动优先；自建浏览器仅辅助本人账号；禁止以绕开检测为卖点 |
| **技术债** | 发布与混剪解耦：混剪输出「物料包」，发布消费物料包，避免引擎里塞满爬虫 |
| **体验** | 客户心智是「早出片、午发完、晚回消息」；App 九页：总览→生产→规则→审片→发布→消息→数据中心→运维→设置；日志在运维内 |
| **自动化** | 免人工步骤必须持久化串成闭环；每次发布在人工窗口内独立随机并留审计；质量失败补产，登录/验证码停人唤回 |
| **即时发布** | 总数按 occurrence 分配到本人账号；成片进入冻结发布组后只续跑本组选定目标，禁止跨批次或同目标重复；即时不改定时 schedule/trigger/seed/窗口；内容与定时共享 ready 池、执行时现挑 |
| **质量** | 口播必须倒逼取片（时长驱动），否则 AI 感去不掉 |
| **运维** | 与质量熔断同构：发布失败连续 N 次停队列；盘未挂载禁生产 |
| **数据** | 片库/成片在同步区；db/cache/cookies 在工作区；消息只存脱敏摘要；cookies 不导出、不注入、不进 T2S |
| **生命周期** | 首个目标提交即隔离；本次全部目标成功后整套物料非删除归档并永久退出可上传片池；结果不明禁止回流 |
| **语义证据** | coarse、目录证据、画面事实与 strict 分层；官方目录辅助规范命名，不替代画面证据和 strict 门禁 |
| **词池/专题** | 词池版本安全演进；物品专题只消费有证据且名称已核验的物品；日/周双配额控制重复 |
| **向量运营** | 最老优先持久队列；交互只入队；状态以落盘事实为准；暂停放弃当前请求并保留已完成 |
| **表达几何** | 标题、字幕、物品名以最终字形外接框做 1080×1920 像素验收，不用 offset/baseline 近似 |
| **竞品差** | 不做「最全自动化」，做「本地实拍 + 可签字日更 + 可带走的发布包」 |
| **范围控制** | 数字人、复杂转场、更大 embedding、全自动私信客服 → 整轮 Reach 完成后再议 |

## 7. 明确不做（写进对内对外口径）

1. 以绕开抖音/快手等 **机器人检测** 为核心能力的方案
2. 无人值守 **全自动多账号矩阵** 养号/群控
3. 未授权抓取他人内容或绕过平台登录验证
4. Phase 1 未完成前，大规模投入发布爬虫
5. 把「软文站群 SEO」做成速影主路径（**允许** Gate GContent：客户自有官网/多域名与本人官方账号的品牌知识运营；**禁止**站群、矩阵铺量、伪装新闻）
