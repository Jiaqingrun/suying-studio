## 1. 一句话定位

**速影**是装在任意客户本机上的 **通用「剪辑 + 发布物料 + 辅助触达」工作室**：

把**该客户自己的**实拍片库，稳定变成 **能发的竖屏成片 + 配套文案/字幕/口播物料**，并在可控风险下 **辅助多平台发出与触达**。

- **产品**通用；**行业包**可插拔；**客户实例**只换路径与配置。  
- 「北京始峰伟业」= 首个样板客户，不是产品边界。  
- 不是矩阵引流黑产工具，也不是全自动数字人直播间。

## 2. 你真正想做的是什么（目标澄清）

| 你心里的诉求 | 澄清后的产品目标 | 明确不是 |
|--------------|------------------|----------|
| 认真做完混剪项目 | 成片质量可签字、日更可运营 | 堆功能清单 |
| 多平台软文同步 | **一次成片 → 多平台文案适配包** | 替客户写无关软文站群 |
| 视频一键发布 | **发布队列 + 半自动/官方通道**，稳定发完配额 | 「绕开平台机器人检测」的全自动矩阵 |
| 多语言字幕/口播 | **人话脚本 → TTS → 声画同构成片** | 一上来就做数字人假脸 |
| 后台消息统一管理 | **未读提醒中枢 + 一键跳转官方端** | 全能跨平台客服台 / 硬扒私信绕登录 |

核心价值排序（优化后）：

```text
1. 成片「能发不丢人」（质量）
2. 每天稳定出够条数（产能）
3. 发出去有配套文案/字幕/口播（物料）
4. 发出去省事、可审计（分发）
5. 发出去之后知道有没有人找（触达提醒）
```

## 3. 做出来能做什么（能力地图）

### 对任意开通客户日常意味着什么

| 场景 | 今天/近期能做 | 完整方案落地后能做 |
|------|---------------|--------------------|
| 早上 | 挂盘 → 开 App → 扫新货 | 同上 + 日历自动开跑 |
| 出片 | 主题混剪、有 BGM、质检进 ready | Logo、打回学习、质量日报（按客户隔离） |
| 发前 | 人肉想文案、自己上传 | **一键导出：视频+封面+各平台文案+字幕+口播** |
| 发布 | 手动打开各 App 上传 | **队列里点「打开并填好」或官方 API 发；验证码时人工点一下** |
| 多语言 | 基本没有 | 英/其他语言旁白+字幕的成片变体 |
| 售后触达 | 各 App 里翻私信 | **速影里看未读摘要，点一下跳进官方端回复** |
| 换公司 | 改代码/改脚本风险高 | **新建客户 + 选行业包 + 指路径**，不改引擎 |

### 产品分层（对外可讲的三档）

| 档 | 名称 | 交付物 | 卖点一句话 |
|----|------|--------|------------|
| **Studio** | 混剪工作室 | 成片 + sidecar + 审片 | 片库进、能发的竖屏片出 |
| **Pack** | 发布物料包 | 文案多平台适配 + 字幕 + 口播轨 | 发出去不用再憋文案 |
| **Reach** | 触达助手 | 半自动发布队列 + 消息提醒 | 少切换 App，不碰风控红线 |

## 4. 总路线图（优化后冻结顺序）

**原则：不平行堆功能；前一层完成定义未过，不开下一层主开发。**

```text
Phase 0  生产可用性
    外置盘/工作区挂载 · 引擎可跑 · 权威库唯一
        ↓
Phase 1  成片可签字（质量冲刺收口）     ← 当前主线
    L0 标尺实锤 → A 有声 → B 实效 → C 可运营
        ↓
Phase 2  发布物料（Pack）               ← 你新增诉求的「高价值且可控」部分
    多平台文案适配 · 多语言字幕/口播 P1 · 导出包
        ↓
Phase 3  声画同构口播（Pack 深化）
    先脚本/TTS 定时长 → 再按句取片混剪 · 去 AI 腔
        ↓
Phase 4  触达助手（Reach）
    半自动发布队列（人在回路）· 消息提醒中枢
        ↓
Phase 5  日更运营闭环（Ops）              ← 当前主线 G6
    旧片补旁白/字幕 · 运营看板 · 发布留痕 · 客户健康
        ↓
明确不做 / 永不作为卖点
    绕开平台检测的全自动多账号矩阵 · 硬对抗风控 · 未授权数字人口播假脸
```

与旧文档关系：

- Phase 1 = [`V8_QUALITY.md`](V8_QUALITY.md)（含 Sprint C）
- Phase 2–4 = 原「明确后置：多平台发布」的**拆分优化版**（不再一锅端）

## 6. 从各角度优化后的设计取舍

| 角度 | 优化结论 |
|------|----------|
| **商业** | 先卖 Studio 质量，再卖 Pack（文案口播），Reach 作加价项；不把封号风险写进承诺 |
| **合规** | 官方/半自动优先；自建浏览器仅辅助本人账号；禁止以绕开检测为卖点 |
| **技术债** | 发布与混剪解耦：混剪输出「物料包」，发布消费物料包，避免引擎里塞满爬虫 |
| **体验** | 客户心智是「早出片、午发完、晚回消息」；UI 按日更时间线，不按工程师模块 |
| **质量** | 口播必须倒逼取片（时长驱动），否则 AI 感去不掉 |
| **运维** | 与质量熔断同构：发布失败连续 N 次停队列；盘未挂载禁生产 |
| **数据** | 片库/成片在同步区；db/cache/cookies 在工作区加密；cookies 进钥匙串 |
| **竞品差** | 不做「最全自动化」，做「本地实拍 + 可签字日更 + 可带走的发布包」 |
| **范围控制** | 数字人、复杂转场、更大 embedding、全自动私信客服 → 整轮 Reach 完成后再议 |

## 7. 明确不做（写进对内对外口径）

1. 以绕开抖音/快手等 **机器人检测** 为核心能力的方案  
2. 无人值守 **全自动多账号矩阵** 养号/群控  
3. 未授权抓取他人内容或绕过平台登录验证  
4. Phase 1 未完成前，大规模投入发布爬虫  
5. 把「软文站群 SEO」做成速影主路径（软文 = 成片配套与公众号长版适配，不是独立媒体矩阵）

## 9. 对外一句话 / 对内一句话

- **对外：** 速影是装在你电脑上的短视频日更工作室：用你自己的实拍素材，稳定产出能发的竖屏片，并自动备好各平台文案和口播，发布少费事、可留痕。  
- **对内：** 质量未签字不开 Pack；Pack 未稳不开 Reach；Reach 人在回路；**第二个客户零分叉**（只加配置）。  
- **工程：** 一切开发遵守 [`DEVELOPMENT_STANDARDS.md`](DEVELOPMENT_STANDARDS.md)。
