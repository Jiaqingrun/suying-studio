## 1. 这是什么

速影是装在**客户自己的苹果电脑**上的「剪辑 + 发布物料 + 辅助触达」工作室。

它做的事情可以一句话说完：

**把你们自己拍的现场视频，稳定做成能发的竖屏（或横屏）成片，并配好各平台文案、字幕和口播；需要时，再在人看着的前提下，辅助发到抖音、视频号、小红书、快手，并把各平台消息提醒到本机。**

它不是：

- 帮你在云端代剪、代发、代管号的公有云套餐；
- 手机里那种「拖两条素材、套一个模板」的轻剪辑App；
- Premiere / Final Cut 那种一帧一帧精修的专业时间线；
- 保证上热门、保证过审、保证不封号的营销黑盒。

合同里的产品分层，对外可以这样理解：

| 档 | 客户能拿到什么 | 一句话 |
|----|----------------|--------|
| 工作台（Studio） | 入库、分析、出片、审片 | 片库进，能发的成片出 |
| 物料包（Pack） | 视频、封面、四平台文案、字幕、口播 | 发出去不用再临时憋文案 |
| 触达助手（Reach） | 发布队列、可选自动点发、消息提醒 | 少切App，登录和验证码仍要人过 |
| 软文辅助（Content，按采购） | 品牌稿、站点变体、半自动发布 | 只做你们自己的官网和本人账号，不做站群 |

未勾选的模块，合同上不构成交付义务。本文按本机已实现能力说明；装机以许可证和附件一勾选为准。

## 2. 适合谁，不适合谁

### 适合

- **有真实经营现场**的公司：仓库、门店、工地、护理店、展厅、车间等，能持续拍到「镜头里真有货、真有人、真有动作」的素材。
- **需要日更短视频**，但不想每次都从空白时间线剪起的团队。
- **素材必须留在自己电脑里**，不接受默认把片库传到供应商公有云的客户。
- **可以接受「人在回路」**：登录、验证码、最终是否发出、私信怎么回，仍由你们自己的人决定。
- **愿意按统一规格拍摄**：竖屏就全库竖屏，横屏就全库横屏，不混用。

本机权威库里已经同时存在多家客户实例（见第12节），说明产品按「换公司只换配置、不改软件」来做，不绑死某一家样板客户。

### 不适合

- 没有实拍、只想用AI凭空生成假现场的。
- 希望买一套软件就**无人值守群控很多账号、自动过验证码、保证不被平台处罚**的。
- 需要电影级调色、逐帧特效、复杂包装片头的广告精修。
- 电脑不是苹果芯片（Apple Silicon）的Mac。合同默认授权设备是单台Mac。
- 拍出来大量虚焦、黑场、横竖混用，又不接受系统拒收的。

## 3. 客户说明项（请逐条看完）

下面这些是客户侧最容易误解的地方。每一条都能在合同、代码或本机设置里对上。

1. **软件装在你们的电脑上。**片库、成片、登录态默认留在本机。不设「默认传到速影公有云」。更新包走约定的载体通道，**片库和成片不上更新盘**。
2. **你们是内容主体。**速影提供工具和技术服务，不是广告公司、不是账号托管方，也不承诺任何平台的流量或审核结果。
3. **只用有权使用的实拍。**员工、顾客、路人、未成年人、他人场地和招牌，须有必要同意。音乐、字体、商标、声音克隆的授权是客户责任。
4. **拍摄有规格。**合同附件三的目标是：生效7日内不少于300条合格素材，并尽快把库填到1000条；分辨率1080×1920或1920×1080；全库统一一种画幅；推荐手持云台（大疆G7或书面同级）配合手机。
5. **糊的、方向不对的进不了可用库。**虚焦、严重发糊、横竖判断不清的素材会被标记拒绝，不能拿去出片。这是写死的质量底线，不是「差不多就行」。
6. **成片要过完整检查才能进「可发」。**文件在、有声音、字幕跟得上说话、不贴边、表情不进旁白、时长盖得住口播——缺一项都不能当成品发出。
7. **发布默认是人点。**软件可以备好标题、正文、视频路径并打开官方页面。若要程序代点「发布」，须另行签署高风险确认，且验证码、登录墙必须人过。
8. **全机同一时间只发一条线。**不会做多开浏览器同时群控。这是为了稳，也是为了不踩矩阵红线。
9. **消息只读摘要，不自动回复。**点「去回复」只打开官方页面，由人自己打字发送。
10. **默认口播会联网。**出厂默认把旁白文本交给微软Edge在线语音合成。若要改成本地音色，须另装运行套件，且相关模型多为非商用许可，未清权不得当可任意商用。
11. **换一家公司不必改软件。**新建客户、指片库路径、选行业包即可。禁止靠「在程序里写死某公司名字」来定制。
12. **宣传口径不得突破合同。**不得把口头「全自动、保证不封、保证过审」理解成交付义务。

## 4. 客户每天怎么用（先看操作，再看原理）

桌面里有九个固定入口，按做事顺序排：

| 页 | 客户怎么理解 | 实际管什么 |
|----|--------------|------------|
| 总览 | 今天卡在哪、下一步点哪 | 混剪剩余、审片剩余、可发条数、消息待办 |
| 生产 | 做片子 | 任务、片库、日更或跟镜精品 |
| 规则 | 片子长什么样、用什么声音 | 标题、字幕、旁白、画幅、精品包装（默认关） |
| 审片 | 过片子 | 抽检、批量修复、自动过审与人工不确定项 |
| 发布 | 发出去 | 视频发布、定时任务、软文（若采购） |
| 消息 | 回话 | 视频号/短视频消息与软文消息，两套分开 |
| 数据 | 看数 | 只读的产能与质量数字 |
| 运维 | 养机器 | 引擎、本地模型、备份、同步、日志 |
| 设置 | 客户与盘 | 客户名、路径、品牌、账号、通知 |

第一次使用（向导）：填客户名 → 指片库、成片、词池路径 → 可选行业包 → 选择是否开启「把片段做成可检索索引」（默认关）→ 全量扫描入库 → 再生产。

日常三步（视频发布，见客户操作说明）：登录一次本人账号 → 勾选账号、填条数、点开始 → 只有登录/验证码、结果不明、或系统提示停止时才需要人回来。

## 5. 主流程：从拍摄到消息

下面按真实链路讲解。每一步都写「客户要做什么 / 软件做什么 / 卡住怎么办」。

### 5.1 拍摄（软件之外，但是整条产线的第一公里）

速影**不内置相机App**。它假设你们已经用手机（加云台）拍好了现场。

合同推荐做法：

- 用能稳定输出约定分辨率的手机，配手持云台（大疆G7或同级）；
- **全库统一竖屏或统一横屏**，不要今天竖、明天横混在一个客户库里；
- 拍「镜头里看得见」的东西：货、车、门头、操作、店内动线。不要靠后期旁白去编画面里没有的情节；
- 避开严重虚焦、大段黑场、侵权或违法内容。

为什么软件这么较真：后面的入库会检查清晰度和横竖方向。拍糊了不是「剪的时候再救」，而是**直接不能当合格原料**。缺景别、缺门头、缺产品特写，也不是靠特效能补的，需要补拍。

客户要做的：按统一规格拍；保证肖像和场地合法；拍完按约定备份进极空间，好让电脑侧能拉进片库。

### 5.2 传输（手机 → 极空间NAS → 本机片库）

日常主路径用**极空间NAS做传输中介**，不靠每天拔线、隔空投送或U盘来回拷。真实链路是：

```text
手机现场拍摄
  → 手机相册备份到极空间（团队空间约定文件夹，如「手机相册备份/某人」）
  → 本机已登录极空间客户端
  → 速影侧单向拉取：只从约定远端文件夹拉到该客户「01-片库」对应目录
  → 片库监视发现新文件 → 自动入库质检
```

客户用人话理解成四步：

1. **拍完就进极空间。**拍摄手机按约定把新片备份到极空间团队空间里**该客户绑定的那一个文件夹**（不是整盘相册乱倒）。
2. **电脑保持登录极空间。**本机客户端在线，速影才能从NAS取片。
3. **软件只拉、不推。**从极空间拉到本机片库；远端删了，本机已落下的文件**不跟着删**，避免误清原料。
4. **落到片库后自动收货。**监视程序发现新视频就入库；也可以在App里点一次全量扫描补漏。

边界（对照真实实现，避免误解）：

- **按客户隔离：**每家客户只绑团队空间`/public`下的**一个**来源文件夹，拉到该客户自己的`01-片库`子目录；第二家客户另绑另拉，来源互不重叠。
- **未配好来源就不开拉：**没有有效来源配置时同步直接拒绝，**不会**把整个`/public`或全家相册灌进片库。
- **片库与更新载体分开：**极空间上的「速影载体/更新包」只负责安装与升级；**片库、成片不走更新载体同步**。媒体拉取是另一条、按客户登记的通道。
- **权威数据库仍在本机系统盘。**数据库、登录态不放在U盘格式或网盘同步盘上随便新建空库。
- **应急补救：**极少数情况仍可用数据线、隔空投送或拷贝盘，把文件直接放进该客户片库目录；日常交付与样板现场以极空间中介为主。

客户要做的：手机端按约定备份；本机极空间保持登录；片库路径可写、磁盘别太满（本机门禁要求至少约10GB可用空间）。传输卡住时，先查极空间是否在线、来源文件夹是否绑对，再查片库监视是否在跑。

### 5.3 入库（看成片之前的「收货质检」）

监视程序会在片库里发现新视频。支持的常见封装包括mp4、mov、mkv、avi、m4v、webm。

入库时软件会做这些事（客户不必会技术名词，但需要知道结果）：

- **读出真实显示方向。**很多手机、云台拍出来的文件，内部标记是横的，实际拿起来看是竖的。软件以「人眼看到的方向」为准，不瞎转第二次，避免画面横竖颠倒。
- **抽几帧检查是否发糊。**模糊超过门槛，整条标为拒收，不能拿去检索、不能拿去出片。
- **记下时长、尺寸、有没有音轨。**出片默认会去掉现场原声，改用旁白加背景音乐，所以现场声不是必须，但成片必须有音轨。
- **做成低码预览。**分析用预览，成片渲染仍按规范后的时间对准原片，避免「看的是小样、导的是错帧」。

客户在列表里会看到：可用、待处理、发糊拒收、方向拒收、失败。发糊和方向问题应回去补拍或换片，而不是央求「先凑合出」。

### 5.4 分析（让软件「看懂」这是货架还是装车）

入库之后，系统会把长视频切成可用小段，并尽量看懂画面里是什么场景、什么物品。目的只有一个：**出片时尽量用对的画面配对的话，而不是随机乱切。**

这里有三条客户能听懂的原则：

1. **先快速、后严格。**新片子可以先进入普通索引，保证低配电脑也能先出片。更严的「画面证据」只对真正要拿去成片的候选段按需核验。不会默认把整个片库用最大模型挨个看一遍——那会把普通电脑拖死。
2. **模糊的、方向不对的，分析也拒收。**质量门在分析之前就拦住。
3. **「目录里有这个货」不等于「这帧画面里看见了这个货」。**官方产品目录只能证明名录，不能代替眼睛看见。专题片只允许围绕画面里真正出现、并且名称核对过的物品来写。

向量化（把片段做成可检索索引）**默认关闭**，要在运维页手动打开。打开后默认是增量：已有的保留，只补缺口。本机开发库当前也是关着的，分析模式为「按需」。

客户要做的：片库分类尽量清楚；需要「越来越准」时再开索引，并接受它会占时间和磁盘。不需要把这项理解成「必须先全部分析完才能出第一条」。

### 5.5 生产（真正做片子）

生产页创建任务：要几条、什么主题、日更还是跟镜精品、用哪套已保存的规则。

软件内部顺序，用人话讲是：

1. **先写能念的口播，再合成声音，量出真实时长**，然后按这句话去片库里取匹配的画面。不是先瞎剪一长条再硬配音。
2. **选片会避开最近刚用过的片段和句子**，减少「每天同一段货架、同一句口号」。近的多用过就先排除，实在不够才逐步放宽。同一条成片里，同一段原片最多用一次。
3. **标题、字幕、旁白语言、音色、语速会冻在这一次任务上。**你在规则页改了明天的样式，不会悄悄改掉正在做的这一批。
4. **口播是主声，背景音乐垫在下面**，现场原声默认去掉。音乐优先用该客户「04-音乐」目录里的曲子，没有再退回全局曲库。曲库须是可商用的免费署名音乐，不要去下榜单热歌。
5. **有旁白时，成片必须比旁白更长一点。**话说完画面不能先黑掉。软件会优先把略长的口播轻轻加快去贴画面；还是长，就冻住最后一帧补齐。禁止把画面裁到比人声还短。
6. **字幕跟嘴走：**一句话说完，字幕就灭；两句之间的空隙不留上一句；左右留出边，避免贴边被平台裁切；中文按短句换气，不把一整段字墙糊在屏幕上。字幕在成片里只烧一次，出包装时禁止再烧一层导致重影。
7. **表情可以出现在字幕里，旁白绝不把表情念出声。**标题区不允许贴表情干扰识别。
8. **连续失败会熔断停工**，避免一台机器对着错误规则空转。本机设置的连续失败阈值为5次。同一时间渲染路数为1，保证机器稳、也保证发布时不会抢资源。

两种常见出片方式：

- **日常日更：**按行业词池和主题，稳定产出可发短片。生活服务类另有倾听口径和禁词，避免空话套话。
- **跟镜精品：**像店主带着镜头把店或仓走一遍。没有真实库存的站位（例如库里根本没有门头）**不会安排进片子**。禁止拿万能金句硬配不相干画面。

客户要做的：在规则页保存并启用一套规则；需要精品包装（开场强调、片尾卡、浅色调）时再打开，这些默认是关的，避免日更被特效拖慢。看总览上的「混剪剩余」，不要在路径异常时强行开跑。

### 5.6 审片（人眼签字前的关）

成片出来后，不是文件在硬盘里就算可发。

自动侧：各项检查都通过的，会自动审核通过并生成发布物料。硬失败自动拒绝。只有「证据不够、门禁缺失、互相打架」才进人工不确定队列。

人工侧：审片页可以像小影院一样抽检；可以筛出没旁白、没烧字幕的旧片，限量批量重做。打回的原因会留下，便于下次少犯同样的错。

客户要做的：抽几条真的看完、听完。自动过审提高效率，但不替代「这片发出去丢不丢人」的人眼判断。合同里的质量冲刺标尺是：成片观感能签字；随机抽5条，「能发」至少4条。

### 5.7 发布物料（发出去之前的「打包袋」）

审核通过后，系统必须为一批视频准备完整物料，缺一不可：

- 成片视频和封面；
- 中文文案，覆盖抖音、视频号、小红书、快手四套（同一卖点、不同说法）；
- 字幕文件；
- 禁词扫描通过。

任一平台文案或视频合同不完整，成片会标成「物料不全」，**进不了立刻发、定时发、自动发的候选池**。这是为了避免「视频发出去了，标题是空的」。

文案默认**不**强制加「本作品由AI生成」。设置里有可选开关，依法需要时再开，出厂是关的。

客户要做的：在设置或词池里维护禁词（例如绝对化用语、医疗承诺、虚假时效）。行业不同，禁词不同：仓配和护理店不能共用一套胡话。

### 5.8 发布（人在回路的四条路）

正式视频平台就四个：抖音、微信视频号、小红书、快手。账号在本机独立的浏览器配置里登录，**不是把别人的登录文件拿来换号**。

四条路，风险从低到高：

| 方式 | 谁点「发布」 | 适合 |
|------|----------------|------|
| 半自动（默认） | 你们自己 | 最稳，风控最低 |
| 单条辅助点击 | 程序代点，须确认风险 | 已登录、只发当前这一条 |
| 马上批量 | 勾选本人账号后串行代点 | 一次发完今天的量 |
| 窗口定时 | 到点后走同一套程序 | 每天在时间窗里自动发 |

共性（四条都遵守）：

- 本人账号、本机浏览器、一次一条线；
- 登录、验证码、滑块、安全验证 **必须人过**，软件不会自动破解；
- 不以「绕过平台检测」为卖点；时间窗里的随机秒是为了排期可审计、重启不重抽，不是伪装人工；
- 已经点了发布但结果不清楚时，只允许「我确认已发布」或先去作品列表确认「没发出去」再补，禁止直接再传一次造成双发。

封面：各视频平台固定1张竖封面，来自App里当前选用的模板。小红书网页封面编辑器经常不好用，系统允许跳过封面、用平台默认帧继续发，并记下「封面待补」。视频号封面会按官方更接近6:7的比例适配。

客户每天：选账号、填条数、点开始。卡住就按页面提示回来处理，不要连点。

### 5.9 消息（发完之后有没有人找）

消息巡检会定时去看**已经登录的本人账号**有没有新提醒。固定间隔30分钟。正式Chrome在后台静默打开官方页面，不弹窗打扰。

客户能看到的：未读数量、对方昵称、脱敏后的短摘要、跳转官方回复的链接。

客户不能指望的：

- 软件替你把回复发出去；
- 保存完整聊天记录、手机号等敏感信息；
- 把「速影自己的待办」伪装成平台真的有未读。

范围：视频四平台 + 软文四平台（百家号、头条号、知乎、微信公众号）为正式支持范围。快手网页目前只确认通知中心，**不能当成可在网页里回私信**；软件必须标明「通知、无网页回复」。未完成真实登录的平台必须显示「需要登录」，不得虚报「已巡检完成」。

通知可以同时走：App提示、macOS系统提示、可选的外部通知。外部通知只发脱敏摘要和链接。本地把某条标已读，只表示速影这边处理过，不会去点平台的已读按钮；再次巡检时，已读的不会装成新消息复活。每账号只保留最近30天、最多200条摘要。

视频消息和软文消息的浏览器配置是分开的，避免一个登录态串到另一个业务。

## 6. 延伸与附加能力

这些不是「主路径之外的玩具」，而是让工作室能长期运转的配件。未采购的模块仍以合同勾选为准。

### 6.1 规则实验室

用白话或面板把「标题多高、字幕什么颜色、旁白什么语言、要不要卡拉OK」写成一套规则，**人工保存启用后才生效**，并冻到新任务。客户规则只能加严，不能关掉成品检查或把糊片放进来。

精品可打开包装：开场强调、物品名微动、片尾卡、浅色调、画布拖标题、多层蒙版（最多8层）、白名单内的字体和转场。日更默认关，避免每条都变成重特效。

### 6.2 多语言

旁白和字幕可选简体中文、繁体中文、英、日、韩以及西、葡、法、德、意、俄、阿、印地、泰、越、印尼、马来、土耳其、波兰、荷兰等，共20种，也可关闭旁白或字幕。同一条画面可以出不同语言的表达。单语烧录时，字幕语言必须跟旁白语言一致，避免「嘴里说中文、字幕却是另一套模板」。

### 6.3 品牌与词池

每家客户有自己的显示名、颜色、Logo位置、封面模板、禁词和词池版本。词池有修订号和校验，发布用的是当时冻结的那一版，不会在出片中途被另一人改乱。新客户可在约一刻钟内走完：建客户 → 指路 → 导词包 → 扫库 → 预览，**不必改程序**。

### 6.4 软文中枢（若采购）

面向客户自有官网和本人账号，根据已登记的事实写稿、出平台变体、人工审核后半自动发布。验证码停人。成功以「已发布地址或平台任务号」为准，不以「点了一次」冒充发出。明确不做：软文站群、伪装媒体、百科营销自动提交、未校准平台标成已支持。

### 6.5 盒盖与睡眠

合上盖、系统睡眠时，可暂停速影自己的任务；醒来再继续。**不会**把你已经点的人工暂停、质量熔断、验证码等待自动清掉。正在对外发布、写盘同步、安装更新这类「有外部副作用」的动作，中断后要人确认，不会偷偷重放一遍造成重复发布。

### 6.6 更新、备份与许可

- 更新：签名安装包经约定载体到本机，客户点击安装。覆盖升级换App，保留片库、词池和登录态。
- 备份到载体：配置级，不含大视频。
- 许可：绑这一台设备。体验期3×24小时全功能；正式默认年期365天（到期全屏锁定，联系运维续签）；也可签发买断。不设公网心跳远程掐死。体验与正式都**不设每日制作/发布条数上限**，但失败熔断和单线发布仍在。

### 6.7 数据中心与运维

数据页提供只读数字，避免口头「感觉出了很多」。运维页集中引擎启停、本地模型、向量、磁盘清理（有允许/禁止范围，不会顺手删系统或无关盘）、日志。高级功能用系统钥匙串密码保护。

## 7. 横评对照（能力对比，不是买榜）

说明：下表是把速影**已经写进代码和合同的能力**，对照市场上常见的几类工具。这不是第三方实验室对某品牌的实测排行，也不评价具体竞品的版本号。目的是帮客户判断「我到底在买哪一类东西」。

| 你真正要解决的事 | 速影 | 常见手机剪辑App | 常见专业剪辑软件 | 常见云端成片或矩阵工具 |
|------------------|------|-----------------|------------------|------------------------|
| 素材从哪来 | 客户自己的实拍；经极空间NAS拉进本机片库 | 相册或模板素材 | 任意时间线素材 | 上传云端或AI生成画面 |
| 数据默认放哪 | 本机片库；极空间只做传输中介与更新载体，片库不上更新盘 | 常绑定个人云账号 | 本机工程文件 | 供应商云盘 |
| 一家公司一套库 | 按客户隔离，换公司不改软件 | 基本是个人账号作品 | 靠文件夹人工分 | 多看供应商是否真隔离 |
| 日更十几条还是精修一条 | 为日更产线设计，规则冻在任务上 | 适合偶尔发一条 | 适合广告精修，日更成本高 | 常强调条数，质量门因产品而异 |
| 糊片、方向错会不会混进去 | 入库就拒；成品还有总检查 | 通常靠人眼 | 靠剪辑师 | 少见与速影同级的写死拒收 |
| 话和字幕齐不齐 | 话说完字幕灭，只烧一次 | 看模板 | 靠剪辑师对齐 | 参差不齐 |
| 发出去有没有各平台文案 | 四平台文案必须齐，缺了不能进待发 | 通常要另写 | 与发布无关 | 有的有文案，不保证四平台齐套 |
| 发布怎么点 | 默认人点；代点须确认风险；验证码停人 | 导出后再上各App | 导出后再上各App | 常见多开/群控话术；速影明确不做 |
| 私信怎么办 | 只读摘要，官方页人工回 | 无 | 无 | 常见自动回复；速影明确不做 |
| 换行业 | 换行业包和词池 | 换模板 | 重做工程 | 看是否绑死行业 |
| 风控承诺 | 书面写明不保证不封、不过验证码 | 一般不碰发布 | 不碰发布 | 部分以「防检测」为卖点；速影禁止该卖点 |
| 机器要求 | 苹果芯片Mac，按内存分档装模型 | 手机即可 | 高配工作站 | 浏览器或云端 |

对照之后，速影的优点可以收成六句，且都能在后文证据里核对：

1. **本机优先：**片子和账号留在客户设备上。  
2. **实拍优先：**用现场，而不是用生成视频冒充经营。  
3. **产线完整：**拍摄 → 极空间中介传输 → 质检入库 → 看懂画面 → 出片 → 审 → 物料 → 发 → 消息，在一个App里接上。  
4. **质量有闸：**糊、方向错、字幕拖尾、口播比画面长、物料不全，都过不去。  
5. **人在回路：**该人决定的环节，软件不替你闯。  
6. **可复制到第二家公司：**配置走行业包和客户目录，不靠改程序。

速影相对「大而全剪辑软件」的代价也很清楚：它**不替代**专业时间线；你要一条电影感TVC，仍应去精修工具。相对「轻App」的代价是：要按规格拍、要有Mac、要接受不合格片被拒。

## 9. 质量底线（用人话解释「为什么有的片出不来」）

客户最常问的是：「为什么这条不能发？」对应关系如下。

| 你看到的现象 | 实际原因 | 正确处理 |
|--------------|----------|----------|
| 入库变成拒收 | 发糊，或横竖方向说不清 | 补拍；不要降低门槛 |
| 预览方向和手机上不一致 | 文件内部旋转标记和画面不一致 | 以软件显示审核为准；禁止再手动乱转一次 |
| 任务停了 | 连续失败熔断，或磁盘/路径不健康 | 先看运维页，修片库或规则再恢复 |
| 成片在失败目录 | 成品总检查未过（无声、黑场、字幕拖尾、时长盖不住旁白等） | 看失败原因，改规则或补素材 |
| 不能点发布 | 四平台物料不齐，或封面/文案门禁失败 | 补物料，不要强制发 |
| 发布停住 | 登录、验证码、结果不明 | 人处理；结果不明禁止再传 |

成品总检查（进「可发」之前）包括：文件够大且质检通过、静音和黑场不超标、禁止用假语音冒充、画幅必须是冻结的1080×1920或1920×1080、标题和字幕样式与任务一致且不越界、字幕对齐口播、左右边距足够、中文短句换气、旁白参数符合锁、表情规则、画质、在启用严格语义时每个镜头都有合格来源、成片时长大于完整旁白。

这些不是「开发者洁癖」，而是避免把不能发的片子堆给客户日常。

## 10. 明确不做（请当优点来理解）

把「不做」写清楚，是为了保护客户账号和双方合同边界：

- 不自动回复私信或评论；
- 不提供反检测浏览器、自动过验证码、Cookie池换号、多开群控、矩阵养号；
- 不保证平台不处罚、不上热门、审核一定过；
- 不替客户取得拍摄对象、音乐、字体、商标授权；
- 不把未校准的平台标成「已经能发」；
- 不把粗索引冒充成「画面已经严格看过」；
- 不把core安装包说成已经自带可商用的本地克隆模型。

这些限制写在合同第2.4条、触达非目标说明和产品硬规则里。

## 14. 把优点说完整（对应前面每一段）

1. **从拍摄就进产线：**不是「有个剪辑软件就行」，而是规格、条数、云台、权属一起约定，后面的闸才有意义。  
2. **传输以极空间为中介：**手机备份到NAS约定文件夹，本机单向拉进片库再入库；只拉不推、按客户隔离来源，不会默认灌整盘相册。  
3. **入库即质检：**糊的、方向错的进不了可用库，避免垃圾进、垃圾出。  
4. **分析为出片服务：**先能出、再求准；目录名不能冒充画面事实。  
5. **生产像车间而不是像艺术工作室：**口播定时长、对题取片、避重、规则冻结、声画对齐、一次烧录。  
6. **审片可自动但不撒谎：**过了总检查才叫可发；不确定的仍进人。  
7. **物料齐套才许排队：**四个平台文案缺一不可。  
8. **发布可省事，不可闯红灯：**人点是默认；代点要知情；验证停人；结果不明不双发。  
9. **消息能叫醒人，不替人说话。**  
10. **第二家公司可复制：**行业包 + 客户目录 + 零分叉验收。  
11. **本机与许可边界清楚：**数据在哪、什么会联网、到期怎么办，都能事前说明。  
12. **优点建立在「拒绝」上：**拒绝糊片、拒绝不齐的物料、拒绝反检测卖点——这些拒绝本身就是给客户的保护。

## 16. 建议客户怎么验收（人话版）

1. 用你们自己的竖屏实拍（不要用网上下载的模板片），经极空间约定文件夹拉进片库（或应急直接放入片库），确认能入库，糊的会被拒。  
2. 保存一套规则，出若干条，戴耳机听完：旁白是否像人话、字幕是否在话停时消失、有没有重影字幕。  
3. 打开物料文件夹：四个平台的文案是否都在、是否触发了你们自己的禁词。  
4. 用**一个本人账号**走一遍「打开官方页、人点发布」。不要用验收去测群控。  
5. 登录后看消息页是否出现摘要；点「去回复」是否只打开官方页。  
6. 合盖再开盖，确认生产能安全停、能续，且不会把一条发布重发两次。

验收通过，只说明这台授权设备上的交付基线可用。它仍然不是流量保证书。
